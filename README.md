# 婚礼现场互动系统

> 大屏投屏 · 签到墙 · 祝福弹幕 · 幸运抽奖 · 摇一摇
> 一套 H5 即可跑通整套现场互动，支持单机演示与真机跨设备两种模式。

---

## 三种部署模式

| 模式 | 适用 | 跨设备 | 需要 |
|------|------|--------|------|
| **本地单机** | 演示 / 试玩 / 一台大屏 + 一台手机 | ❌（同机多窗口） | Python / Node / 任何静态服务器 |
| **真机跨设备** | **婚礼现场**（推荐） | ✅ | 局域网 + `node server.js` |
| **微信小程序** | 主办方希望出现在微信里 | ✅ | 已认证小程序 + HTTPS 域名 + 备案 |

> 💡 同一套 H5 代码走完三种模式，业务逻辑不重复实现。

## 30 秒上手

### 模式 A：本地单机（最快验证）

```bash
cd wedding-live
python -m http.server 8080
# 或：npx serve -l 8080
```

浏览器打开 `http://localhost:8080/`，会看到引导页：
- **大屏端** → 投屏到电视 / 投影仪
- **宾客端** → 同一浏览器开多个标签即可模拟多位宾客

> ⚠️ 直接用 `file://` 打开**不行**：跨设备同步依赖 `BroadcastChannel` 与 `localStorage`，同源策略下 `file://` 不可用。务必起一个 HTTP 服务。

### 模式 B：真机跨设备（**婚礼现场**）

```bash
cd wedding-live
npm i
node server.js
```

启动后控制台会打印：

```
=== 婚礼互动服务已启动 ===
  本地访问：  http://localhost:8080/
  手机扫码：  http://<电脑局域网IP>:8080/
  WebSocket： ws://<电脑局域网IP>:8080

手机端必须带 ?ws= 参数才会走真机同步，例如：
  http://192.168.1.100:8080/mobile.html?ws=ws://192.168.1.100:8080
```

操作步骤：
1. 确认主持电脑和宾客手机都连到**同一个 Wi-Fi**
2. 大屏浏览器打开 `http://192.168.1.100:8080/screen.html`（**不要**带 `?ws=`，大屏单机模式更稳定）
3. 宾客扫码后，地址自动带上 `?ws=` 参数，手机端走 WebSocket 同步
4. 也可以单独把大屏也改成 `?ws=` 让所有端都连服务端（如果想让两台电脑分别投屏）
5. **主持人手机**扫大屏右上角的「🎙 主持控台」二维码（或直接访问
   `http://192.168.1.100:8080/host.html?ws=ws://192.168.1.100:8080`），
   可遥控切画面、抽奖、游戏与弹幕开关
6. 数据自动持久化到 `data/state.json`（头像在 `data/avatars/`），断电重启不丢

> **网络提示**：部分酒店 Wi-Fi 做了 AP 隔离，宾客之间无法互访。遇到这种情况：
> - 让酒店用手机开个 4G 热点
> - 或换一台支持访客模式的路由器
> - 电脑插网线、宾客连 Wi-Fi 通常没问题

### 模式 C：微信小程序

> 套壳项目位于 `miniprogram/`，详见 [转换为小程序](#转换为小程序)。

## 功能详解

### 签到墙（大屏中央）

- 宾客扫码 → 填名字 → 选 emoji 头像（或上传照片）→ 大屏心形头像墙实时出现
- 头像位置按**对数螺旋**均匀分布于心形：人少时清晰、人多时不挤
- 超过 300 人自动切换为**网格墙**模式
- 新加入的宾客会高亮 3 秒

### 祝福弹幕

- 宾客写祝福语 + 选快捷模板 → 大屏右侧列表 + 全屏飘屏弹幕
- 大屏可开「**审核模式**」（设置里）：新人审核通过的才上墙
- 内置敏感词过滤，挡住现场可能的不当内容

### 幸运抽奖

- 多奖项（默认：一/二/三等奖），可在大屏「⚙ 设置」里任意增删改
- 滚动 → 停止 → 显示中奖卡片动画
- 已中奖的嘉宾自动从奖池剔除，不会重复
- 快捷键：**空格** = 开始/停止抽奖
- 重抽本轮会清空当前奖项的记录

### 摇一摇赛马

- 大屏按「**开始游戏**」→ 3 秒倒计时 → 30 秒内疯狂摇手机
- 实时排名：每条进度条按摇动次数填满
- 陀螺仪不可用时**自动降级**到点击模式（圆圈），老年机和 iOS 锁屏都能玩
- iOS 需要 HTTPS 才能开陀螺仪，详见下

### 设置

- 新郎/新娘姓名、副标题（日期/地点）
- 弹幕开关、审核开关
- 奖项自定义
- 危险操作区：清空中奖/祝福/全部数据

### 快捷键

| 键 | 作用 |
|----|------|
| `1` | 切到签到墙 |
| `2` | 切到幸运抽奖 |
| `3` | 切到摇一摇 |
| `空格` | 当前舞台是抽奖/游戏时，开始/停止 |
| `Esc` | 关闭设置弹窗 |
| `F` / `F11` | 浏览器全屏 |

## iOS 摇一摇的 HTTPS 限制

iOS Safari 13+ 在**非 HTTPS** 网站下完全屏蔽 `devicemotion` 事件，这是苹果的隐私保护策略。

**三种应对方案**：
1. **简单**：用点击模式（圆圈点击加分），iOS 全程可用
2. **进阶**：在 H5 前加一层 Cloudflare / Caddy / Nginx 反代，启用自签名/正式证书
3. **推荐**：用微信小程序加载 H5，强制走 HTTPS

> 摇一摇的核心逻辑是「加速度变化触发计分」，点击是同等有效的兜底通道。本系统始终保留两种入口。

## 部署到生产

### 公网部署清单

- [ ] 服务器：1 核 2G 起步（婚礼现场 200 人并发也够）
- [ ] HTTPS 证书：Let's Encrypt 免费，或阿里云 / 腾讯云证书
- [ ] 域名：必须 ICP 备案（中国大陆境内访问）
- [ ] 防火墙：放行 443 端口（或自定义）
- [ ] 启动方式：`pm2 start server.js --name wedding-live`
- [ ] 静态资源：H5 本身是纯静态，可放在任何 CDN（OSS / COS + CDN）

### 简易部署（内网穿透）

婚礼现场没有公网也没关系：
- 主持电脑用 `cpolar` / `frp` / `tailscale` 暴露局域网端口
- 宾客扫码访问临时域名

### 上线前 24 小时必查

- [ ] 用真实手机测一遍签到、祝福、抽奖、摇一摇
- [ ] 测一次断网重连：拔网线 10 秒再插上，看数据是否恢复
- [ ] 准备一个「备用手机」当主持人控制台（万一大屏卡了）
- [ ] 婚礼前一天关掉所有浏览器/系统通知，避免大屏弹出中奖通知等尴尬

## 转换为小程序

> 套壳策略：H5 全部代码进 `web-view`，**H5 端任何更新立即生效，无需重发版**。

### 前置条件

1. 已认证的微信小程序账号（个人订阅号**没有** web-view 权限，必须是**已认证**的企业/个体/媒体号）
2. 一份**已 ICP 备案**的域名 + **HTTPS 证书**
3. H5 部署到该域名（参考上面「部署到生产」）

### 操作步骤

1. 用微信开发者工具打开 `miniprogram/` 目录
2. 填入你的 AppID（在 `project.config.json` 替换 `touristappid`）
3. 修改 `app.js` 的 `globalData.h5Base`：
   ```js
   this.globalData.h5Base = 'https://wedding.your-domain.com'
   ```
4. 微信公众平台 → 设置 → 第三方设置 → **业务域名**：
   - 添加 `wedding.your-domain.com`
   - 下载校验文件放到 H5 根目录并部署
5. 提交审核（约 1-7 天）

### 小程序里的「宾客端」与「大屏端」

默认进入 `mobile.html`（宾客端）。如果你希望从同一个小程序进入大屏端：
- 给大屏端做一个独立入口（如 `pages/screen/index`），web-view 加载 `screen.html?ws=...`
- 大屏在会场电脑运行，不通过小程序，但扫码同一个小程序也能让主持人在手机上控场

## 自动化测试

```bash
# 启动服务
node server.js &

# LocalStore 模式（同 context 多页面，22 项断言）
NODE_PATH=<全局node_modules> node tools/verify/smoke.js

# WebSocket 模式（不同 context 模拟跨设备，10 项断言）
NODE_PATH=<全局node_modules> node tools/verify/smoke-ws.js
```

### QR 编码正确性

`tools/verify/compare_qr.py` 把本项目的 QR 编码器与 Python `qrcode` 库做 6 个测试用例 × 8 种掩码的矩阵对比。**48/48 全通过**意味着：
- 数据编码、Reed-Solomon 纠错、模块放置、掩码选择、格式信息全部符合 ISO/IEC 18004
- 任何标准扫码 App 都能识别

## 故障排查

### 手机扫码后只看到「请用本地服务器打开」

→ 你的 H5 是用 `file://` 打开的，必须用 HTTP 协议（参见「30 秒上手」）。

### 大屏手机端都已签到，但头像墙是空的

→ 看右上角「已签到」数字。若是 0：检查是否在不同 Wi-Fi 下。
→ 若不是 0 但墙是空的：刷新大屏，或打开「⚙ 设置 → 重置全部数据」再让宾客重签。

### 抽奖按下「开始」没反应

→ 浏览器可能拦截了点击，确认下控制台。
→ 大屏无嘉宾时不允许抽奖（先有签到）。

### 摇一摇毫无反应

→ 大屏的「摇一摇」必须先点 **开始游戏**。
→ iOS 设备：先点击「开启摇一摇感应」按钮授权陀螺仪。
→ 直接点击大圆也可参与（点击 = 摇一次）。

### 弹幕飘到一半消失了 / 卡住

→ 这是 Web Animations API 在某些安卓机上的 bug。把该行弹幕拖到屏幕外即可，或等下次刷新。

### WebSocket 连不上（真机模式）

→ 控制台看到「正在连接同步服务…」但迟迟没反应：检查防火墙 8080 端口。
→ 修改端口：`PORT=9000 node server.js`，手机端地址也改成 `:9000`。

## 自定义指南

### 改婚礼主题色

打开 `css/common.css`，修改 `:root` 下的 CSS 变量：
```css
--wine: #6d1f2c;     /* 酒红 */
--gold: #d4af37;     /* 香槟金 */
--rose: #e8b4b8;     /* 玫瑰粉 */
```
所有页面都会跟着变。

### 改奖项默认值

打开 `js/store.js` 里的 `createDefaultState()`，修改 `config.prizes`。

### 改快捷祝福语

打开 `js/mobile.js` 顶部的 `QUICK_BLESSINGS` 数组。

### 增加新的数据字段

1. 在 `store.js` 的 `createDefaultState()` 加字段
2. 在 `Actions` 里加 mutator 函数
3. 在 `screen.js` / `mobile.js` 的 render 函数里渲染
